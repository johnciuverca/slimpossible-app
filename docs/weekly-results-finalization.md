# Weekly group results

Weekly awards lock at Sunday 20:00 Europe/Bucharest and require an actual, explicitly group-shared weigh-in dated on that Sunday. The baseline is selected in this order: an actual shared weigh-in on the previous Sunday; linear interpolation from actual shared records bracketing that Sunday (the current Sunday may be the later endpoint); or, when no earlier actual record exists, the member’s first actual shared weigh-in Monday–Saturday of the current week. No extrapolation or estimated weigh-in qualifies. A first-ever Sunday record is a baseline only for the following week. Actual Sunday recorders and members eligible with a usable baseline are counted separately.

The provisional result locks Sunday at 20:00 Europe/Bucharest. Source writes acquire the same challenge/Sunday advisory lock before the database samples the gate. A transaction admitted before the cutoff may finish after it; finalization waits for that transaction and snapshots its committed state. Writes admitted at or after the cutoff cannot change that Sunday. Multiple scopes are locked in a stable order.

Private candidate rows freeze each member’s current actual shared weight and baseline value with its source date or interpolation endpoints. They exclude unshared/private records and evidence outside the membership episode or admitted after cutoff. The lazy finalizer writes one immutable result and winner evidence; later source edits cannot alter an award. A competitive award requires at least two eligible members; a sole eligible member and a challenge with one active participant receive no competitive win. Estimates remain chart-only and never create actual weigh-in records.

The migration does not initialize the rollout. The restricted service-role initializer requires a future effective Sunday and seeds each existing group's finite Sunday horizon. New groups are seeded by a database trigger. Historical results before the selected effective Sunday continue to use the existing actual shared Sunday calculation and remain read-only; no award backfill occurs. The approved first effective Sunday is **2026-11-22 at 20:00 Europe/Bucharest**, conditional on Staging readiness. If testing is not complete before that cutoff, select a later future Sunday; never initialize for a cutoff that has passed.

Account erasure removes personal weigh-ins, notes, avatar objects, legacy member weigh-ins/milestones, invitations, private candidates and detailed winner evidence. A finalized win remains as an anonymous `Deleted member` row; its winner count and other members' awards do not change. Challenges survive with a null owner/creator reference. Challenge deletion remains owner-only; the lifecycle for an archived ownerless challenge needs an explicit product decision. The Edge Function first marks erasure using a service-role-only RPC. Avatar uploads take a matching per-user advisory lock and are rejected while that marker exists, so an in-flight upload completes before cleanup scans Storage. Storage files are removed before Auth deletion; if cleanup fails, the marker remains and the caller can retry. The Auth trigger performs relational scrubbing. No existing account or challenge is deleted by this migration.

## Local verification

Run `supabase/tests/run_local_group_weekly_results.sh` to create a disposable PostgreSQL cluster, apply the migrations, check the Bucharest DST boundaries and strict cutoff, verify private snapshots and immutable awards, and exercise deterministic multi-scope locking. The script uses only a local Unix socket and does not configure logical replication or scheduled jobs.

This local proof does not initialize staging or production and does not establish hosted SQL acceptance. See [weekly-results-staging-rollout.md](weekly-results-staging-rollout.md) for the approved Staging backup, read-only preflight, migration, and initializer sequence. The rollout remains disabled until Staging verification is complete and an owner runs the service-role initializer for the approved future Sunday. Production/Live requires a separate release decision.
